## 1. 设计目标

把识饵从「Gophish 资源清单工具」收成「演练与意识提升工作台」。


| 目标   | 说明                                                |
| ---- | ------------------------------------------------- |
| 任务闭环 | 选场景 → 圈人 → 开演练 → 看风险 → 跟进 / 汇报                    |
| 主路径短 | 培训负责人约 10 分钟内可完成：导入或选人 → 选中文场景 → 测试 → 启动 → 读懂结果结论 |
| 结论优先 | 结果页先回答「怎样了、谁弱、谁要跟进」，事件明细后置                        |
| 轻量定制 | 留白充足、层级清晰、品牌可辨；不做高密度企业组件库皮肤                       |
| 双语静默 | 中英随 `Accept-Language`；界面无手动语言开关                   |


**非目标：** 营销官网式首页、内置 AI 对话助手、把配置页做成面向最终员工的自助门户。

---



## 2. 用户与默认路径



### 2.1 意识培训负责人

关心：本季是否按计划演练、覆盖了谁、举报/点击是否改善、给领导的一页纸结论。

- 默认落地：**工作台**
- 主按钮：**从场景发起演练**
- 高频页：工作台、演练列表、结果（结论区）、场景库



### 2.2 安全运营

关心：进行中演练是否健康、高风险名单、部门对比、能否快速复测。

- 默认落地：**工作台**（卡片权重偏「待跟进 / 发送异常」）
- 高频页：工作台、演练结果明细、目标人群、发送通道（排障时）

同一套导航；差异用工作台卡片权重与空状态文案体现，不做两套产品。

## 3. 信息架构



### 3.1 导航结构（目标态）

参照 KnowBe4 / usecure 等主流控制台：**浅色顶栏 + 业务域文字导航**（不用开发工具式窄图标轨，也不用 Gophish 资源平铺侧栏）。

```text
┌──────────────────────────────────────────────────────────────────┐
│ 识饵   工作台  演练  场景库  人群  报告     [发起演练]  设置▾  用户 │
└──────────────────────────────────────────────────────────────────┘

设置▾
  · 发送通道 / 发信配置
  · 邮件模版 / 钓鱼页面（标「高级」）
  · 账号设置
  · 用户管理 / Webhooks（仅管理员）
```

**原则**

- 一级入口按业务域命名，最多五项；设置与基础设施不进一级。  
- 全局主操作：**发起演练**（顶栏实心按钮；工作台可重复）。  
- 「报告」一等公民（服务甲方汇报），不只藏在单场结果页。  
- 系统管理仅管理员在「设置」中可见。



### 3.2 路由与旧名对照


| 旧（现状） | 新（界面文案） | 备注 |
|---|---|---|
| 仪表盘 | 工作台 | URL 可仍为 `/` |
| 行动 | 演练 | URL 可仍为 `/campaigns` |
| 用户 & 组 | 人群 | |
| 邮件模版 / 钓鱼页面 / 通道 / SMTP | 收入「设置」 | 高级与基础设施 |
| （无） | 场景库 | 创建演练主素材入口 |
| （无） | 报告 | 管理层简报与跨场汇总 |
| （无） | 顶栏「发起演练」 | 全局主操作 |
内部 API / 模型字段可继续使用 `campaign` 等英文名；**对用户文案**统一用「演练 / 场景 / 目标人员 / 风险」。

### 3.3 核心用户流

```text
工作台 ──「从场景发起」──► 发起演练向导（4 步）──► 演练进行中
                              │
场景库 ──「用此场景发起」──┘
                              │
演练列表 ──「新建」───────────┘
顶栏「发起演练」──────────────┘

演练 / 工作台 ──► 演练结果（结论 → 名单 → 部门 → 明细）
报告 ──► 管理层简报 / 跨场汇总（导出）
```

启动演练必须由**人在管理端点击确认**（或带显式确认令牌的 API）；不提供 AI/自动化默发入口。详见 AI/API 相关决策文档。

## 4. 视觉设计



### 4.1 调性

冷静、清晰、数据可读；对齐企业安全意识控制台习惯，同时保持识饵轻量定制。

- **壳层**：浅顶栏 + 文字主导航（行业常见）；内容区白/浅灰纸面。  
- **主色**：苔藓绿，不用 KnowBe4 式信息蓝密集皮肤，不用深色图标轨作默认壳。  
- **工作台**：以「易中招率」类主指标开场（对标 Phish-prone % 心智），配一句话结论与建议动作。  
- 一屏一事；少嵌套卡片；状态色克制。  
- 参考：`docs/ui-redesign-demo.html`、`docs/ui-competitive-research.md`。



### 4.2 设计令牌（实现时落 CSS 变量）


| 令牌 | 建议值 | 用途 |
|---|---|---|
| `--ink` | `#101a16` | 图标轨、结论/英雄深底 |
| `--paper` | `#f3f6f3` | 页面底 |
| `--panel` | `#ffffff` | 面板 |
| `--text` | `#15201b` | 主文字 |
| `--text-3` | `#6d7f74` | 说明、表头 |
| `--line` | `#d5dfd8` | 分割线 |
| `--moss` / `--moss-deep` / `--moss-soft` | `#1b7a55` / `#125c3f` / `#d9efe4` | 主按钮、选中 |
| `--sand` / `--clay` / `--teal` | 琥珀 / 砖红 / 青绿 | 关注 / 危险 / 改善 |

字体：中文优先「Noto Sans SC」或系统黑体；西文可配清晰无衬线。避免为「好看」引入与业务无关的展示字体。

圆角约 `8–10px`；主内容区留白大于现状 Bootstrap 仪表盘；表格行高略增，便于扫读。

### 4.3 组件约定（轻量定制）


| 组件   | 约定                               |
| ---- | -------------------------------- |
| 主按钮  | 实心品牌绿；每页主操作不超过一个视觉焦点             |
| 次按钮  | 白底 + 线框                          |
| 状态胶囊 | 进行中 / 关注 / 改善 / 需补训；颜色克制，文案优先于色块 |
| 表格   | 轻表头、行悬停浅底；进度用细条而非大饼图堆砌           |
| 空状态  | 说明下一步（导入人群 / 选场景），禁止只写「还没有行动」    |
| 弹窗   | 简单 CRUD 可用；**发起演练不用巨型单页弹窗**，改向导  |


地图：结果页降权（可折叠或默认隐藏）。部门表与高风险名单升权。

### 4.4 响应式

以桌面管理端为主（≥1100px）。窄屏顶栏导航可收为抽屉；向导步骤改为单列。不保证古老内网浏览器。

### 4.5 可视化约定

| 场景 | 图表类型 | 说明 |
|---|---|---|
| 组织风险趋势 | 折线（双系列） | 易中招率、举报率；横轴月份 |
| 部门对比 | 横向条形或分组柱 | 点击 / 提交；颜色用令牌，忌彩虹 |
| 单场转化 | 漏斗 | 发送→打开→点击→提交→举报 |
| 覆盖率 / 完成度 | 环形或进度弧 | 报告与工作台次级指标 |
| 上场对比 | 双柱 | 本场 vs 上场关键率 |

原则：图表服务结论句，不替代文案；默认 2～4 张，避免仪表盘饼图墙；实现阶段可用 ECharts / Chart.js / 现有 Highcharts（许可清晰时）。

## 5. 页面规格



### 5.1 工作台 `/`

**目的：** 打开后立刻知道组织风险水平、在跑什么、下一步做什么（对标 KnowBe4 Dashboard + Hoxhunt 建议动作）。

**布局**

1. **英雄指标卡**：近 30 天易中招率大数字 + 环比 + 一句话态势；旁侧次级指标  
2. **可视化区（必有）**  
   - 近 6 个月易中招率 / 举报率折线趋势  
   - 部门横向对比条形图（点击 / 提交）  
3. 双栏：进行中的演练 | 建议下一步  
4. 部门风险表（与条形图互补，可点选下钻）  

**空状态：** 引导导入人群 → 打开场景库 → 发起演练。

---



### 5.2 演练列表 `/campaigns`

**目的：** 管理进行中 / 已归档演练。

**布局**

- 顶栏：「发起演练」主按钮
- Tab：进行中 | 已归档 | 回收站
- 表格列建议：名称、场景/手法标签、通道、创建时间、状态、关键率（点击或提交，择一作摘要）、操作

**交互**

- 「发起演练」进入向导（非旧版单 modal 填全字段）。
- 行操作：进行中为查看结果、复制、归档；已归档为查看结果、复制、删除（移入回收站，可恢复）。
- 回收站行操作：恢复到已归档（不重新发信）；彻底删除需二次确认。规格见 `docs/campaign-soft-delete.md`。

---



### 5.3 发起演练向导（P1，首选小岛）

**目的：** 场景驱动创建（对标 usecure 模板库分步 / KnowBe4 Create Campaign 整页）。

**步骤（固定 4 步，页顶横向步骤条）**


| 步   | 标题    | 内容                                   |
| --- | ----- | ------------------------------------ |
| 1   | 选择场景  | 展示内置场景包卡片（分类、难度、手法标签）；可选「从已有模版创建」进高级 |
| 2   | 选择人群  | 用户组；部门/标签过滤；显示预计触达人数（去重）             |
| 3   | 通道与时间 | 通道默认跟场景匹配（邮件/短信/即时通讯）；启动时间；可选均匀发送截止  |
| 4   | 预览与确认 | 摘要只读；「发送测试给我」；「确认启动」                 |


**高级选项（折叠，不挡主路径）**

- 多步骤邮件、逐步落地页、Reply 触发、自定义 URL、指定 SMTP 配置等现有能力。

**规则**

- 未完成必填不可进入启动；启动按钮文案明确为确认发送。
- 测试发送与正式启动分离，避免误触。

---



### 5.4 演练结果 `/campaigns/:id`（结果页）

**阅读顺序（强制）**

1. **结论区**：一句话态势 + 关键比率  
2. **可视化区（必有）**  
   - 漏斗图：发送 → 打开 → 点击 → 提交 → 举报  
   - 与上场对比的分组柱状（可选）  
   - 部门对比条形图  
3. **高风险名单**  
4. **明细与原始事件**；地图默认折叠  

**页头操作：** 刷新、导出、完成演练、（P3）生成管理层简报。

**实现：** P0/P1 可先调区块顺序与文案；P2 强化名单与部门交互。

---



### 5.5 场景库 `/scenarios`（新建）

**目的：** 浏览内置中文场景包，并一键进入向导（对标 usecure / KnowBe4 模板库心智）。

**布局**

- 筛选：分类（日历/二维码/办公附件/短信/即时通讯/多步骤/回复等）、难度、手法、行业
- 卡片：标题、简述、标签、难度；操作「预览」「用此场景发起」
- 次入口：「管理自定义模版/页面」链到内容素材

数据来源：`models/scenariopacks/` 的 manifest 与元数据。

---



### 5.6 人群 `/groups`

**目的：** 维护演练对象；部门字段支撑结果分层。

**增强点（相对现状）**

- 文案改为「目标人群」；导入 CSV 引导更明确。
- 列表可见成员数、部门覆盖摘要（若数据允许）。
- 与向导步骤 2 的选择器字段对齐。

---



### 5.7 报告 `/reports`（新建）

**目的：** 服务甲方汇报与跨场汇总（对标 KnowBe4 Reports 一等公民）。

**布局**

- 卡片入口 + **内嵌图表预览**（趋势折线、部门柱状、覆盖率环形）  
- 操作：生成 PDF/打印、导出 CSV  
- 可从单场结果「生成管理层简报」跳入并预填该场  

### 5.8 内容素材与配置（设置菜单内）

邮件模版、钓鱼页面、发送通道、发信配置：保留编辑能力，入口在「设置」，不进一级导航。

### 5.9 登录 / 重置密码

保留现有流程；品牌「识饵」、令牌色与管理端一致。无语言切换器。

## 6. 文案与术语


| 对用户（zh）  | 对用户（en 建议）                                                  | 避免                       |
| -------- | ----------------------------------------------------------- | ------------------------ |
| 演练       | Campaign / Drill（产品内统一选一词，建议 Campaign 对外、界面可用 Drill 时需全站一致） | 「行动」单独作导航名               |
| 场景 / 场景库 | Scenario                                                    | 只说 Template              |
| 目标人群     | People / Groups                                             | 「用户 & 组」工具腔              |
| 工作台      | Workbench / Home                                            | 空「Dashboard」无说明          |
| 高风险名单    | High-risk people                                            | 只说 Results 无解释           |
| 发起演练     | Launch drill                                                | Launch campaign 可作 API 名 |


空状态、按钮、错误提示全部走 `i18n/locales/zh.json` 与 `en.json`；小岛内禁止硬编码。

品牌：界面与标题后缀使用「识饵」。

## 7. 与方案 B 的实现分工


| 阶段 | UI 交付 | 技术 |
|---|---|---|
| **P0** | 导航与文案、工作台初版（含趋势/部门图）、结果页区块重排、CSS 令牌 | Go 模板 + 现有 JS/图表库 + CSS 变量 |
| **P1** | 发起演练四步向导；场景库列表页；创建路径切离巨型 modal | 向导优先小岛；场景库可用模板 |
| **P2** | 工作台/结果完整图表与筛选；高风险名单强化 | 工作台/结果小岛 |
| **P3** | 管理层简报（含图）导出、培训闭环标记 | 仍在方案 B 内扩展 |


验收以本节页面规格与第 1 节目标为准，不以「是否引入某框架」为准。

## 8. 无障碍与体验底线

- 表单控件有可见 label；主操作可达键盘。
- 状态不只靠颜色（配合文字胶囊）。
- 危险操作（删除演练、捕获密码类开关）有确认与警示文案。
- 加载中有明确指示；接口失败可读、可重试。

## 10. 开放问题（不阻塞 P0）

1. 英文界面「Campaign」与「Drill」最终用词需产品拍板（全站统一）。
2. P3「管理层简报」优先 PDF、还是先 Markdown/HTML 打印。
3. 「待补训」标记是否写库持久化，或首期仅导出名单由线下跟进。
