刚接手「识饵」时，我不会先堆功能，而是先把产品定位和用户价值说清楚：这是给安全团队做**钓鱼演练与意识提升**的平台，不是又一个开源 Gophish 镜像。基于你们已有的分叉（中英双语、品牌、本地化），我会按下面方式推进。

### 前两周：摸清现状，再谈优化

1. **明确服务谁**  
   主要用户是甲方安全运营、意识培训负责人，还是给安全公司交付演练的服务商？两种路径的优先级完全不同：前者要「开箱即用、报表能交差」；后者要「多租户、白标、批量交付」。

2. **跑通一次完整演练**  
   从建组、写信、落页、发信、点开/提交、到报表导出，自己走一遍，记下卡点：中文是否齐、状态是否好懂、失败原因是否可诊断、报表能否直接给领导看。

3. **盘点相对上游的差异资产**  
   识饵品牌、i18n、端口与部署习惯已是差异化起点。接下来要决定：是做「更好用的中文 Gophish」，还是做「意识培训业务系统」。后者才值得持续投入。

### 产品定位建议

上游 Gophish 强在「能发、能追、能记」。识饵应再进一步，强调：

- **演练可交付**：场景模板、合规话术、结果可读  
- **对中国环境友好**：中文默认体验、常见企业邮箱/网关适配、报告模板  
- **安全可解释**：明文存密码等风险要产品化提示，而不是埋在设置里  

一句话定位可以是：  
**「面向国内团队的钓鱼演练与安全意识平台」**，而不是「Gophish 中文版」。

### 我会优先改的五件事（按价值排序）

**1. 演练结果「能交差」**  
现状偏工程师视角（事件流、状态码）。管理层要的是：点击率、凭据提交率、部门对比、高风险人群、改进建议。  
优先做：中文结果页、一键导出「管理层摘要」、场景对比（同模板多次演练）。

**2. 场景资产库，而不是从空白表单开始**  
多数用户不会写钓鱼信。应内置合规可用的场景包：邮箱验证、VPN、快递、HR 调薪、IT 重置密码等，含邮件 + 落页 + 注意边界（避免真实仿冒品牌侵权）。  
这是最能拉开与「裸 Gophish」差距的点。

**3. 发信成功率与可诊断性**  
演练失败往往卡在 SMTP、SPF、证书、网关拦截。产品要给出：测试发送结果、常见失败原因中文说明、发送画像健康检查。  
没有「发得出去」，其他功能都是空的。

**4. 把 i18n 做完、做稳**  
模板已双语，但 JS 弹窗、状态文案、图表标题仍可能中英混杂。作为中文产品，默认路径必须是完整中文；英文随浏览器即可。  
同时补回 MIT 许可证与版权声明，为对外发布做合规准备。

**5. 权限与审计（面向企业）**  
谁创建了演练、谁导出了结果、谁看了提交的凭据——这在甲方是刚需。先做操作日志和敏感数据访问控制，再考虑复杂 RBAC。

### 中期（1–2 个季度）方向

| 方向 | 为什么重要 |
|------|------------|
| 多租户 / 项目隔离 | 服务商或集团安全部刚需 |
| 演练编排（计划、提醒、复测） | 从「发一次」变成「意识项目」 |
| 与企微/钉钉/邮箱网关的弱集成 | 提高触达与闭环，不必一上来做深集成 |
| 培训闭环 | 中招后跳转学习页、答题、复测，证明「演练有效」 |
| 部署形态 | 单机包 + Docker 一键，文档中文化 |

### 我会刻意不做的事

- 不要和商业钓鱼平台拼「仿冒库规模」或灰产能力，定位必须是**授权演练**。  
- 不要先做华丽大屏；先把发信、结果、报告做扎实。  
- 不要在上游 `master` 上堆定制；继续用 `shier` 分支/标签，定期 `merge upstream`，避免分叉腐烂。  
- 不要默认可抓明文密码而不做强提示与权限隔离——这是信任与合规风险。

### 90 天路线图（务实版）

**第 1 个月：可用**  
完整中文体验、发信诊断、结果摘要导出、3～5 个合规场景包。

**第 2 个月：可交付**  
管理层报告模板、部门/标签维度、敏感操作审计、部署与升级文档。

**第 3 个月：可增长**  
中招后培训页、复测对比、（按客户需求）多项目管理或简易多租户。

### 成功怎么衡量

不看「功能数量」，看：

- 新人无协助完成一次演练的时间  
- 发信成功率 / 失败自助解决率  
- 报告被直接用于汇报的比例（是否还要再导 Excel 改格式）  
- 单季度复测客户占比（有没有形成培训闭环）
